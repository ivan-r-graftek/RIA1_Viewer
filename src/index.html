How to use this tool

This page reads the file names and timestamps of a key images day folder, either directly (on the RIA server) or from a CSV made by the script, and derives every timing figure from them. CSVs from the older RIA_KeyImage_Timing script (_files.csv, _summary.csv) also load.

A. On the RIA server: browse the folder (no script needed)

  1. Copy this HTML file to the RIA server, for example to the Desktop, and open it in Edge or Chrome. It works offline; everything it needs is inside the file.
  2. Click Browse key images folder… and select a day folder:
    E:\RIA Data\Continuous Logs\key images\<yyyy-MM>\<dd>, e.g. E:\RIA Data\Continuous Logs\key images\2026-10\07.
    A month folder (...\key images\2026-10) also works and loads every day in it, but takes longer.
  3. Confirm the browser prompt. Edge and Chrome ask "Upload N files to this site?". Click Upload: nothing leaves the PC. The page only reads file names and Modified times, never file contents, and changes nothing on disk.
  4. Add more days with Add folder. Days are combined on the same charts.

B. Anywhere else: run the script, load the CSV

  1. Click Scripts (top right) and save RIA_scripts.zip. Extract it on the RIA server and unblock RIA_KeyImage_Files_v2.00.ps1 (right-click > Properties > Unblock).
  2. Copy the script into the day folder (E:\RIA Data\Continuous Logs\key images\2026-10\07\), next to the sample folders, and Run with PowerShell. If right-click is blocked:
    powershell -ExecutionPolicy Bypass -File "E:\RIA Data\Continuous Logs\key images\2026-10\07\RIA_KeyImage_Files_v2.00.ps1"
  3. Take KeyImageFiles_2026-10-07.csv from the Desktop, delete the script from the day folder, and load the CSV here with Load CSV…. The CSV also carries Created times, so it gives exact RIA copy times (chart 7) and the ready.txt check.
  4. The zip also contains RIA_Mailbox_Watch_v1.00.ps1, a read-only watcher for the Key mailbox that logs when ready1.txt and BCRT's Ready.txt really appear and estimates the CFG–RIA clock offset. Run it on the RIA server through at least one burst.

Then

  1. Set the options. Camera sets the RIA queue ceiling (Optyx6000 50, Manta 100). Wait ≥ (default 10 s) is the gap between two pickups that counts as RIA waiting. In section 9, Measure and Delayed if ≥ (default 30 s) set the per-sample delayed / on-time tag.
  2. Export. Export to Excel writes Summary, Readings (every sample with its tags), Fits and About sheets. Save charts as PNG saves every chart for Jira or the site.

Before quoting numbers

  • How the list becomes timings: capture is the timestamp in the folder name; RIA pickup is the earliest file Created time; copy end is the latest file Created time; a sample is complete when it holds ready1.txt and bcrt.settings.
  • Capture time comes from the sorter / CFG clock; pickup comes from the RIA server clock. Check the offset with w32tm /stripchart /computer:<CFG IP> /samples:3 /dataonly on the RIA server.
  • The ready.txt inside key images is written by RIA when the move finishes, so it is not a Key timestamp. This page never uses it as one.
  • A folder being in key images does not prove RIA processed it into In-Bag results; compare against the results folder and the Event Viewer queue messages.
Folder mode. The browser can only read each file's Modified time, not its Created time. RIA pickup is therefore taken as the time RIA wrote its own ready.txt (the end of the copy, 0.01–1.5 s after it started), and RIA copy time (chart 7) and the ready.txt Created = Modified check are not available. Intervals, waits and completeness are unaffected. For exact copy times, use the script CSV.

What this measures

  • Capture is the timestamp in the sample folder name (sorter / CFG clock). RIA pickup is when RIA started copying the sample into key images (the earliest file Created time on the RIA server); the copy ends at the latest file Created time.
  • Complete samples carry the BCRT handoff files (ready1.txt and bcrt.settings). Incomplete samples arrived with only frameGrab and header.
  • A wait is a gap between two pickups in the same burst at or above the threshold. Per the mailbox protocol, RIA waits up to 30 s for a sample's ready.txt before moving on.
  • The ready.txt inside key images is written by RIA when the move finishes, so it is not used as a Key timestamp. Capture and pickup come from different clocks; check CFG–RIA clock skew before quoting single-second figures.
ready1.txt vs ready.txt: who writes what

Two marker files with almost the same name mean different things and are written by different systems. Only one of them carries a Key timestamp into key images.
